Zero dependencies

Components that outlive your framework.

Platform is a component library built entirely on native custom elements and CSS custom properties. There is no build step, no runtime, and no dependency tree — because the browser already does this.

Read the docs $ npm i @platformdesign/components

Four fewer things to worry about

Every one of these is a problem the platform solved years ago, and that most component libraries reintroduce.

No toolchain

Ship the source. It's standard ES modules and standard CSS, so a <script type="module"> tag is a complete integration. Nothing to compile, configure, or keep current.

No framework

A custom element is just an HTML element. It works in React, Vue, Angular, Svelte, Rails, Django, a static file — anywhere HTML works. You don't need a port for each one.

No theming API

Custom properties are the only thing that crosses a shadow boundary, so they are the theming API. Override a token in your own CSS and every component follows. No rebuild.

No supply chain

Zero dependencies means zero transitive dependencies. Nothing to audit, nothing that can be hijacked upstream, no postinstall script. The whole library is readable in an afternoon.

The same button, twice

Both render a button. Only one of them still runs in five years.

The usual way

bash
npm i @scope/ui react react-dom
npm i -D vite @vitejs/plugin-react
# 200+ transitive packages
# a config file
# a build before you can look at it

Then: a framework upgrade, a build tool migration, and a rewrite when the library is abandoned.

This way

html
<script type="module"
        src="/components/pl-button/index.mjs"></script>

<pl-button variant="primary">Save</pl-button>

Then: nothing. It's HTML. The browser is the runtime and it doesn't break its own APIs.
